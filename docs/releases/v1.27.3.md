# Version 1.27.3 — Express 5

The first of four dependency-upgrade releases, one per area of risk. This one
is the server, the riskiest of the four because `main` deploys itself.

## What moved

| Package | From | To |
| --- | --- | --- |
| `express` | 4.22.3 | **5.2.1** |
| `@types/express` | 4.17.25 | **5.0.6** |
| `dotenv` | 17.4.2 | **18.0.5** |
| `express-rate-limit` | 8.6.0 | 8.7.0 |
| `@google/genai` | 2.12.0 | 2.27.0 |

`@types/node` stays on 22.x on purpose, to match the Node 22 runtime in the
image. Typing against Node 26 would let code use APIs production lacks.

## What Express 5 changed here

The server was audited against the Express 5 migration list: route-pattern
syntax, `req.query`, removed methods such as `app.del` and `res.sendfile`,
status-code validation and body-parser defaults. One change was needed:

- **The SPA fallback.** Express 5's path-to-regexp v8 no longer accepts a bare
  `"*"` route; a catch-all must be named. `app.get("*")` became
  `app.get("/{*splat}")`. Without it, every deep link such as `/labs` would
  404 in production while the home page still worked, which is exactly the
  kind of failure that passes a smoke test of `/` alone. So the probes below
  test deep links on purpose.

Also revisited: the `query parser` setting. Its comment said to move to
Express 5 "if a route needs nested query syntax". "simple" is now Express 5's
default. It stays explicit, so a future default change cannot quietly put
`qs` back on the request path.

Express 5 also forwards rejected promises from `async` handlers to the error
handler instead of leaving the request hanging. Every async route here already
catches its own errors, so behaviour is unchanged, but the safety net now
exists.

## Verification

- `npx tsc --noEmit` clean against the Express 5 types. `npx vitest run`: 58
  files, 483 tests, green. That includes the HTTP-level server suites:
  cross-site write refusal, rate limits, cookies, revision checks, recovery
  timing, admin gates and the suggestion board.
- Production build on a scratch database:
  - `scripts/smoke.mjs` passed: production page, legacy APIs, scenario
    grading, account registration and saves.
  - Probes: `/`, `/deep/link/path` and `/labs?x=1` serve the app;
    `/api/does-not-exist` is a JSON 404; `/healthz`, `/api/questions` (669)
    and `/api/account/me` answer as before; `HEAD /` is 200.
  - The accessibility sweep, which drives every section through the SPA:
    24 screens, no violations.
- `npm audit`: 0.
- No Docker on this machine. CI's container job runs the image and the smoke
  test, which is the last check before this reaches production.

**Noticed, not changed:** a request for a missing `/assets/*.js` gets the HTML
shell with a 200, from the catch-all, as it did under Express 4. After a
deploy, a browser still holding the old page asks for old hashed chunks and
gets HTML, which surfaces as a MIME-type error rather than a clean reload.
Answering `/assets/*` misses with a 404 would be a small, separate fix.

Delivered by pull request, stacked on 1.27.2. No schema change, no
configuration change.
