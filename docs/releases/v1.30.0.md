# Version 1.30.0 — An account directory for administrators

Owner-requested change to the privacy boundary: an active administrator session
can now load usernames, administrator/learner roles and creation dates. The
console has Load accounts, Refresh and Load more actions, with 50 accounts per
page. Loading is explicit; the directory is not fetched on every console visit.

The database query projects only the three approved fields. It does not join
progress, activity, sessions or recovery data. Ordinary study sessions are
refused, revoked admin sessions are refused, and responses are private/no-store.
The old ability to sign another learner out remains removed. Role changes
remain separate typed actions, including the last-administrator protection.

README and docs/privacy.md now state exactly what administrators can see.
No schema migration or new study key. Two-factor authentication is not added:
the choice of who should require it is still awaiting the owner.

## Verification

- npm run lint; npx vitest run: 60 files, 500 tests passed; npm run build and
  release gate passed. HTTP tests enforce exact fields, a separate admin session,
  no-store responses, invalid-cursor rejection and revocation. A 52-account fixture
  verifies pagination without duplicates or secret fields.
- Real production server with a scratch database: guest and ordinary study-cookie
  requests received 403; an elevated administrator received only the three approved
  fields. Browser Load more displayed all 52 test accounts. Locking the session
  removed the directory and made the API return 403 again.
- Chromium at 1280px and 375px in dark/light themes: directory and pagination
  passed, screenshots inspected, zero axe violations. Fixed header wrapping on
  phones. The CI sweep now includes the directory: 50 screens, zero violations.
- No local Docker run; CI builds and smoke-tests the production image. Two-factor
  enrollment/recovery and assistive-technology testing are not verified or implemented.
