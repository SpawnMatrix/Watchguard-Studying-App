# Version 1.27.0 — Practise against the clock

Mock exams were untimed, so they measured knowledge but not pacing. Running
out of time is a common way to fail an exam you know well enough to pass, and
it is easy to rehearse once there is a clock.

## Timed mock exams

In Practice settings, choosing **Mock Exam** reveals a **Timed exam** option.
Ticking it starts a new exam with a limit of **one minute per question**, so
50 minutes for a full 50-question mock.

That is stated as a practice pace, not as any exam's official limit. The
option says "check your own exam's time limit", because exam rules change and
the portal does not track them; an out-of-date number would mislead exactly
the people relying on it.

- **Clock and pace.** Beside the question counter, `49:57 · on pace`. Pace
  compares questions answered with the share of time used, allowing one
  question of slack either way so it does not flicker while you read a long
  question. *Behind* is shown in red, with a light-mode colour that passes
  contrast.
- **The clock is an absolute deadline stored with the session.** Reloading
  neither pauses nor resets it, and a deadline that passes while the tab is
  closed ends the exam as soon as it is reopened, just as a real exam would.
- **When time runs out**, the exam ends where it is:
  - Questions already answered count as usual. That includes one being graded
    as the clock hits zero: the stale session written afterwards is re-expired
    on the next tick, so the answer is kept and the exam still ends.
  - **Questions never reached count as wrong in the exam score.** A timed-out
    exam is scored out of every question, not just the ones attempted,
    because that is what the exam does.
  - **They are not written to practice history, spaced repetition or the
    weakness deck.** The learner never saw them, so recording them as misses
    would teach the scheduler something false. The results screen says this
    in so many words.
- Finishing early reports "Finished in 32:10 of 50:00, with 17:50 to spare."
- **Screen readers:** the clock is a `role="timer"`, which is not
  announced every second. A separate polite live region speaks the five-minute
  and one-minute marks once each.

Untimed mocks, the Topology Lab's mock exam and practice mode are unchanged.

## Engineering

- `src/engine/examTimer.ts` is pure: start, validate, remaining and used time
  (both frozen once the exam ends), expiry, clock formatting that reads 0:00
  only when time is really up, pace, and the announcement marks.
- `useQuizEngine` gains an optional `timing` on the session. `configure` and
  `reset` keep the timed setting, so changing the topic filter does not quietly
  turn the clock off. One interval ticks while a timed exam runs and drives
  both the display and expiry.
- The shared schema accepts `timing` on a saved quiz session and rejects a
  malformed one, both in the browser loader and on the server.

## Verification

- `npm run lint` clean. `npx vitest run`: 56 files, **474 tests**, green.
  - Timer: one minute per question, expiry at the deadline, clocks frozen
    after the end, rounding, pace with slack, announcement marks, and
    validation.
  - Rendered quiz: a running timed exam shows the clock and pace, an untimed
    mock shows none, a timed-out exam scores "1 of 4 correct · 25%" and
    explains the three unanswered, an early finish reports time used and
    spare, and the server accepts a timed session but rejects a bad timer.
- Driven in a production build: chose Mock Exam, ticked Timed, and the clock
  read 49:59 then 49:57, on pace. Set the stored deadline 3 seconds out and
  reloaded. The clock read "0:02 · behind", then the exam ended with "Time ran
  out with 50 of 50 questions unanswered", and the stored session was complete
  with `timedOut: true`.

Delivered by pull request, stacked on 1.26.0. A saved session without `timing`
is an untimed exam, exactly as before.
