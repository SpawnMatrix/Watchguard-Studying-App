# Version 1.30.2 — Pick up progress from your other devices

A tab left open only found out about saves from another device when its own
next save was refused. Someone who studied on their phone and then went back to
a laptop tab still saw the old progress. Their first answer then raised the
"Choose a save" prompt between the two copies.

## What changed

- When a tab comes back into view, or the connection returns, and nothing on
  this device is waiting to be saved, the portal asks `/api/account/me` for the
  latest save. If it is newer, the tab takes it, the same way signing in does.
  It asks at most every 30 seconds.
- Unsaved local work still goes first, through the normal save and revision
  check, so a real conflict still raises "Choose a save". The check is also
  skipped while the account panel is open.
- If the session ended elsewhere, for example after "Sign out everywhere", the
  status changes to "Sign in to sync" instead of staying on "Saved".
- The decision lives in `src/account/freshness.ts` as a pure function, tested in
  `freshness.test.ts`.

## Verification

- Production build, scratch `DATA_DIR`, two Chromium contexts acting as two
  devices on one account. Device A answers 1 question; device B signs in and
  answers 2 more; A comes back into view.

  | | A on returning | A's next answer |
  | --- | --- | --- |
  | 1.28.2 | 1 answer | "Choose a save" |
  | this release | 3 answers | saved (4) |
- `npm run lint`, `npx vitest run` (61 files, 513 tests), `npm run build`, and `scripts/check-release.mjs` against the parent branch and `origin/main` all pass locally. CI's container job runs on the PR; no local Docker here.
- Not verified: real phones and the browsers' own visibility events. The test
  fires `visibilitychange` itself.

## Deploy impact

Client-only. No server, schema, Compose or image change.
