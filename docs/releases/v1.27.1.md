# Version 1.27.1 — A faster first load

The entry chunk, which is everything a visitor downloads before the first
screen can render, was **434.6 kB (139.3 kB gzip)**. The question data already
loaded per section. The shell itself did not.

## What was in it, and why

A build with a reporting plugin listed every module in the entry chunk by
rendered size. Apart from React, three things did not need to be there:

| Module | Why it was there | Where it goes now |
| --- | --- | --- |
| **motion** (motion-dom + framer-motion, ~125 kB minified) | The shell used it for a 150 ms section fade and the profile dialog | Its own chunk, fetched by the first section that animates |
| **`data/labs.ts`**: every step of all 20 labs | Study Home showed "0 / 20" and suggested labs by name | `data/labIndex.ts`, just the 20 names |
| **`data/changelog.ts`**: the full text of every release | The What's New badge needed a count | `engine/changelogSeen` is imported after first paint |

### Result

**Entry chunk: 263.0 kB, 82.6 kB gzip: 41% less.** Nothing is modulepreloaded
alongside it. On the Home screen the browser now fetches the entry and the
small changelog chunk, and nothing else. Opening Flashcards fetches `motion`
then.

## How

- **The shell animates with CSS.** Sections fade in with a `section-enter`
  keyframe, and the dialog with `dialog-enter`. Both are already covered by the
  global `prefers-reduced-motion` rule. There is no exit animation any more,
  so a new section appears immediately instead of waiting 150 ms for the old
  one to leave. That also ends a quirk where navigation looked frozen in
  background tabs, because the exit animation could not finish there.
- **Reduced motion still reaches the sections that use motion.** The
  `MotionConfig reducedMotion="user"` added in 1.22.2 lived in the shell, which
  no longer imports motion. Every section now imports it through
  `components/motion.ts`, which sets `MotionGlobalConfig.skipAnimations` when
  the system asks for reduced motion. That turns off JavaScript animations
  entirely for those users, a stricter result than before.
- **`labIndex.ts` duplicates 20 lab names on purpose.** `labIndex.test.ts`
  fails if it ever disagrees with `labs.ts`, so the copy cannot drift.
- **The badge count loads with `import()`.** A failed chunk load is caught,
  because a badge must never break navigation. The badge appears a moment
  after the page.

## The guard

`src/firstLoad.test.ts` walks the static import graph from `main.tsx`,
following `import` and `export … from`, skipping `import type` and dynamic
`import()`. It fails if the first load reaches `motion`, `framer-motion`,
`data/labs.ts`, `data/changelog.ts`, `data/flashcards.ts`,
`data/questions.ts`, `engine/catalog.ts` or `engine/mockExam.ts`.

It also asserts the walk finds the shell, so an import-syntax change cannot
make it pass by finding nothing. Run against 1.27.0's versions of the three
changed files, it failed on motion, labs and changelog, which are exactly the
three this release moves.

The exam planner (1.26.0) and flashcard work (1.25.0) were already written to
stay out of the first load. This test is what makes that a rule rather than
care.

## Not done

React DOM is most of what is left, and it is not optional. The question bank,
about 500 kB across `catalog` and `authoredQuestions`, already loads only when
a question section opens. Splitting it per track would make every learner on
one track download less, but `questionById` is used globally across tracks
(weakness review spans all of them), so it is a bigger change than this
release.

## Verification

- `npm run lint` clean. `npx vitest run`: 58 files, **483 tests**, green,
  including the 8 first-load checks and the lab-index parity test.
- `npm run build`: entry 434.6 → 263.0 kB, gzip 139.3 → 82.6 kB. `motion`
  becomes a separate 124.9 kB chunk.
- Driven in a production build:
  - Home fetched only `index` and `changelogSeen`.
  - The What's New badge still showed its count (6).
  - Sections render with the `section-enter` animation.
  - Opening Flashcards then fetched `motion` and rendered a card.
  - The profile dialog opened with `dialog-enter` over a `fade-enter`
    backdrop and closed on Cancel.
  - No console errors.

Delivered by pull request, stacked on 1.27.0. No behaviour change beyond
the transitions.
