# Version 1.23.0 — Answer on the diagram itself

The diagram section was built around the exam's habit of putting a network on
screen and asking *where* something happens. Its renderer has supported
clickable devices and links since 1.2.0. But of the 16 scenario diagrams, only
two (1604 and 1611) had anything to click. The rest asked conceptual questions
whose options were explanations, such as "denied, because no default policy
allows Trusted to Optional traffic", so the drawing was an illustration you
read and then answered beside.

## Companions, not rewrites

Most of those questions cannot be made clickable without becoming different
questions. Their answer sets were balanced for option length in 1.13–1.14,
classified against the exam blueprints in 1.6 and 1.9, and twinned against
the rest of the bank. Rewriting them would undo all three.

So each diagram gets a **companion** instead: a new question on the same
network, testing a fact the original does not, where every option is a device
or link you can click.

| New | On diagram | Asks you to click |
| --- | --- | --- |
| 1616 | Three-zone perimeter | the link where a request still has the SNAT public destination |
| 1617 | Published mail server | the first link where 1-to-1 NAT has changed the source |
| 1618 | Two-site BOVPN | the device that decrypts Site A's traffic |
| 1619 | Dual-ISP failover | where a Link Monitor target belongs to catch an upstream outage |
| 1620 | Two subnets on one interface | the device that routes between primary and secondary networks |
| 1621 | Remote worker | the link where traffic has left the SSL VPN tunnel |
| 1622 | Where inspection happens | the device that validates the site's real certificate |
| 1623 | Which subnet holds the host | the VLAN link a .200 host arrives on |
| 1624 | OSPF cost comparison | R1's first link after the R2–R4 link fails |
| 1625 | DHCP across a router | the furthest device a DHCPDISCOVER reaches without a relay |
| 1626 | Local works, remote does not | the device whose address belongs in the gateway field |

Thirteen of the sixteen diagrams now have a question answered by clicking. The
remaining three have no question I could write that was both unambiguous and
not trivial:

- **1602:** three nodes, and every candidate answer was "the Firebox".
- **1609:** "where to look next after an Allow" has more than one defensible
  answer.
- **1615:** the subnet-sizing diagram has nothing to locate.

`src/data/topologyQuestions.ts` gains a `locate()` helper. A companion names
its base scenario and reuses that network's nodes and edges as they are, so a
corrected address in a scenario corrects its companion too. Each option names
the element a click selects. An option with no element, such as "None; they
share a segment", stays a button.

## Checks on content I wrote

My own notes record shipping an answer-length tell in my own questions five
times, so these were measured before committing:

- **Length:** options are 7–29 characters, below the range where length can
  cue an answer. The key is strictly the longest in 2 of 11.
- **A different tell, caught and fixed:** in the first draft, "The Firebox"
  was the correct answer in **all three** questions where it appeared. On a
  Firebox course, "pick the Firebox" would have been a working shortcut. 1621
  was rewritten so its answer is a link (where the SSL VPN tunnel ends). The
  Firebox is now the answer in three companions and a distractor in two, and
  in one of the three the distractor is the other Firebox.
- **Twins:** five companions would give their partner away in the same mock
  exam, so `questionTwins.ts` keeps them apart. 1617 joins the 1-to-1 NAT
  group, 1618 pairs with legacy 203 (BOVPN encryption scope), and 1623, 1625
  and 1626 pair with their own scenarios.
- **Blueprints:** the four Network+ companions are classified in
  `NETWORK_PLUS_DOMAIN`. Both blueprint tests pass at their existing
  tolerances.
- **Accuracy:** each explanation was checked against the diagram's own
  addresses and Fireware behaviour. One draft overstated SMB signing as a
  confidentiality control and was corrected.

## Counts

669 authored questions (from 658), 497 Local Firebox items (490) and 185
Network+ items (181). `scripts/smoke.mjs` asserts the new 669, and the README
gate added in 1.22.1 failed on exactly these numbers until the README was
updated. That gate now also pins the number of diagram questions answered on
the diagram, 13, so this improvement cannot quietly regress either.
