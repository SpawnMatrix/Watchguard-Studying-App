# Version 1.13.0 — Question bank checked against the Study Guide

Every one of the 630 authored questions, all 62 question generators, the Q&A Desk study notes, the hand-written flashcards and the L1 breakdowns were read end to end. Claims that looked doubtful were checked against WatchGuard's *Network Security Essentials for Locally-Managed Fireboxes Study Guide*. This release corrects the answers and explanations that disagreed with it, and stops mock exams from asking the same fact twice.

## Corrected answers

- **Static NAT.** Several questions taught writing the inbound policy to the server's private address "because NAT is applied before the policy lookup". Fireware doesn't work that way: you add the SNAT action to the **To** section of the policy (Study Guide p. 127). Fixed in:
  - question 1522 (which items publish a server)
  - question 1602 (the diagram question about the policy's To section)
  - the generated "Where the SNAT action goes" question
  - the explanations of questions 38 and 208

  Question 87 also claimed an SNAT action can't use a domain name, but a static NAT action can name an FQDN. It now asks about the two SNAT action types: Static NAT and Server Load Balancing.
- **Mobile VPN with IKEv2 authentication.** Question 56 marked "Active Directory / LDAP" correct. The Study Guide's compatibility table lists Firebox-DB, RADIUS and AuthPoint for IKEv2. Active Directory works only through RADIUS, and LDAP and SecurID aren't supported. The explanations for questions 10 and 1534 now say exactly why LDAP and Active Directory fail the "every VPN type" test.
- **Backup images.** Question 59 said a backup image can go to "an identical model". A backup image restores only to the Firebox that created it (p. 20), because it carries that device's certificates, keys and feature key. Question 1513 now also checks the Fireware version, since an image restores only onto the version it was saved from.
- **Multi-WAN method names.** Four questions used "Spillover", "Routing Table Cost" and "Interface Failover". Fireware's methods are **Failover** (the default), **Round-robin**, **Routing Table** and **Interface Overflow** (pp. 92–102). The questions, options and explanations now use those names and describe them as the Study Guide does.
- **BOVPN failover.** Questions 36 and 1532 said failover "rides on Multi-WAN". Multi-WAN doesn't affect BOVPN traffic. Failover moves between gateway endpoint pairs when Link Monitor marks the link down or dead peer detection finds the peer inactive. It needs two external interfaces with Link Monitor targets and a matching endpoint on the remote Firebox (p. 287).

## Smaller fixes

- **Question 57:** the stem asked about "high-reliability, zero-touch VPN gateway configurations", which isn't a thing. It now asks which IKE version WatchGuard recommends for a new BOVPN gateway, and the explanation gives the Study Guide's reasons.
- **Question 67:** the explanation discussed port 4100, which isn't one of the options. It now addresses the options actually shown.
- **Question 1604:** the explanation said a router blocking ESP stops Phase 1. Phase 1 runs over UDP 500. Blocking ESP lets the tunnel negotiate and then carry no traffic.
- **Generated flood log questions:** a UDP or IPSec flood was logged as TCP. Each flood type now logs its own protocol and port.
- **Generated management-ordering question:** it pointed to a "System → Managed Access" menu that doesn't exist. It now points to the WatchGuard Web UI policy.

## Q&A Desk study notes rewritten

For the Local Firebox track, the Q&A Desk shows 25 written study notes. Several contradicted the Study Guide, and all 25 have been rewritten against it:

- **Management ports:** Firebox System Manager was listed on port 4105 and WatchGuard System Manager on 4118. The WatchGuard policy allows WSM on **TCP 4117** and the CLI on **TCP 4118**, and Web UI uses **TCP 8080** (p. 145).
- **Factory defaults:** Eth2 was described as having no address. Optional interfaces default to **10.0.x.1/24** with DHCP disabled (p. 11).
- **Policy-based BOVPN:** described PFS as "applied directly on the policy action". PFS is a Phase 2 setting, shared by both BOVPN types.
- **WebBlocker:** listed a "Drop" action. The actions are **Allow, Deny and Warn**, and override works by passphrase or user group (pp. 203–208).
- **Multi-WAN:** described Routing Table as ordinary route metrics. It uses **ECMP**, and Failover is the default (p. 92).
- **TDR and Host Sensors:** described as current. **ThreatSync**, WatchGuard's XDR service, has replaced them. The note now covers what ThreatSync correlates, its risk scores and its automation (pp. 62–65).
- **Blocked sites:** permanent and auto-blocked sites were merged. Permanent entries block traffic to and from a site, while auto-blocked entries block only traffic from it. The 20-minute duration resets each time the site is blocked again (pp. 32–33).
- **NAT loopback and 1-to-1 NAT:** the notes now give the Study Guide's steps and caveats.
- **Authentication servers:** SAML was listed and AuthPoint and SecurID were missing. Mobile VPN support by type is now included.

Seven new notes cover high-yield exam topics the desk didn't have: Default Threat Protection, publishing a server with static NAT, Link Monitor, interface types and network modes, the Authentication Portal, log message types, and WatchGuard Cloud for locally-managed Fireboxes. The notes now live in `src/data/qaDesk.ts`, and tests check their formatting and pin the corrected facts.

## Flashcards

The 20 hand-written cards that open the Local Firebox deck repeated several of the same errors, and some had their own. They taught Firebox System Manager on port 4105. An exam tip said to tick an "Enable NAT Loopback" option that doesn't exist; loopback works through the policy's From list. They also described Routing Table multi-WAN as default gateways and static routes. All 20 are rewritten against the Study Guide, including the larger models' different setup interfaces (Eth24 and Eth32). The deck now lives in `src/data/flashcards.ts`, and tests pin these corrections. The deck still has 315 Local cards.

## "Explain like I'm an L1" breakdowns

Several menu paths in these missed-answer breakdowns didn't exist or were in the wrong place:
- Dynamic NAT is under **Network → NAT**, not Firewall → NAT.
- Temporary blocked sites are under **System Status → Blocked Sites**.
- Backups are under **System → Backup and Restore Image**.
- "System → Setup Wizard" isn't a menu. The Web Setup Wizard runs at https://10.0.1.1:8080 on a factory-default device.

The Policies breakdown now explains Auto-Order instead of saying the Firebox simply reads rules from the top down.

## Mock exams no longer ask the same fact twice

The bank grew in passes, so some facts are asked more than once in different words, such as the Authentication Portal port, the default Trusted address, or what NAT loopback is for. In practice that's useful reinforcement. In a mock exam, the first copy gives the second away.

A new curated list groups 58 sets of same-fact questions across all three tracks, and a mock exam now takes at most one question from each group. If that would leave a category short, or a small filtered pool would lose questions, the draw uses the whole pool instead. Practice mode is unchanged.
