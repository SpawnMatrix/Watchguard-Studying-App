## Updater capacity protection

After a production disk-full incident, add a capacity check before fetching and again before building. Check both space and inodes for the checkout, Docker root, and containerd store when present. Low capacity triggers cleanup of unused build cache older than seven days, then a fresh measurement. If headroom remains insufficient or cannot be measured, fail visibly while keeping the running container and data volumes intact. Do not mark a commit as bad for a capacity failure. Existing image retention, backup, locking, health checks, and rollback remain in effect. The installed host script must be updated separately from merging this file.
