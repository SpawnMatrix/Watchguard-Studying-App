# Version 1.3.4 — reach the lab step button again

Fixes a layout regression introduced with the completed lab catalogue in 1.3.0.

Opening a lab showed its objectives and the active step, then a large empty area and nothing else. The step-completion button appeared to be missing, so a lab could be started but never advanced or finished.

The button was never missing. The two lab columns sit in a CSS grid, and a grid row stretches to its tallest item. Going from 8 labs to 20 nearly tripled the catalogue column, so the walkthrough pane inflated to match — measured at 2897 pixels, with its footer correctly pinned at the bottom, 2847 pixels down the page behind the empty space. The control was reachable only by scrolling past nothing.

- Both lab columns now cap themselves to the viewport on large screens and scroll internally, so neither one sets the row height. Measured on the same page: 2897 pixels down to 836, with the step button inside the viewport without scrolling.
- A test asserts the cap is present on both columns and that the step-completion control still exists. The markup was correct throughout this bug, so a render test would not have caught it; the assertion is on the constraint that prevents it.

Anyone mid-way through a lab keeps their progress; step completion is browser state and is not affected by this change.

No SQLite migration, volume replacement, Compose change, or topology v1 contract change is required.
