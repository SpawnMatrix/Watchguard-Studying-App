# Version 1.14.0 — Scenario questions rewritten from the Study Guide

280 scenario questions were too easy to answer without knowing the material. Their stems were generic and their distractors were throwaways. For example, "Why should a feature key from another Firebox not be treated as interchangeable?" offered "Keys contain only display colour settings" as a wrong answer. Every one of those questions is now written from the matching chapter of WatchGuard's *Network Security Essentials for Locally-Managed Fireboxes Study Guide*, or from the matching N10-009 objective. The rest of the bank no longer gives the answer away by option length either.

## What was rewritten

Each rewritten question asks about one specific fact or decision. Its three wrong options are real features, settings or values that don't answer this particular question. For instance, the new question on Force Key Expiration asks what the setting controls and its default: Phase 2 key changes, 8 hours. The wrong options are the Phase 1 SA lifetime, the dead peer detection interval and a traffic-based rekey. Every explanation says why the answer is right and why the most tempting wrong option isn't.

- **Local Firebox, questions 1000–1239 (180 questions):** setup and management, Default Threat Protection and global settings, logging and monitoring, interfaces and static routing, multi-WAN and SD-WAN, NAT, firewall policies, security services, proxies, authentication, Mobile VPN, and Branch Office VPN, 15 of each.
- **Network+, questions 1300–1392 (65 questions):** IPv4 addressing and subnetting, protocols and network services, switching and wireless, the troubleshooting methodology, and operations and security, 13 of each.
- **WatchGuard Cloud, questions 1400–1414 (15 questions):**
  - which settings stay local when a Firebox is added for visibility, and what changes when it is cloud-managed
  - deploying changes
  - templates
  - ThreatSync requirements
  - reports and scheduled reports
  - restoring backup images
  - Live Status diagnostic tools
- **Applied checks, questions 1500–1519 (20 questions):** troubleshooting and multi-select questions that combine several facts.

## Older questions corrected

- **Question 83** asked what sends traffic through a policy-based BOVPN and keyed firewall policies. In a manual BOVPN, **tunnel routes** that match the source and destination decide what enters the tunnel, and policies decide whether it's allowed. The Q&A Desk note on manual BOVPN now says the same.
- **Question 74:** the explanation filed PFS under the gateway (Phase 1) settings. PFS is part of the Phase 2 tunnel settings.
- **Question 89** listed an IP-based match as a wrong answer, but WebBlocker exceptions can be based on IP addresses. That option is replaced with an Application Control signature match, which is genuinely wrong.
- **Question 6** described an SNAT action on port 80 as publishing a "secure" web server and called SNAT a policy. It is now an action that publishes a web server.
- **Question 63** named its own answer: the question said "reputational score" and the key was Reputation Enabled Defense. The question now describes what the service does, and the explanation says how a good score lets content skip Gateway AntiVirus scanning.
- **Question 303:** the explanation now says the Firebox never joins the domain, needs no LDAP or RADIUS broker, and doesn't need Single Sign-On. Mobile VPN with IKEv2 is the exception, because it reaches Active Directory through RADIUS.
- **Question 307:** the explanation cited "Unhandled Packet" as a kind of policy. It now explains that a Denied entry is the Firebox's own decision: a deny policy matched, or no policy allowed the traffic.
- **Question 114:** the wrong options are now the metrics other protocols use (RIP hop count, EIGRP bandwidth and delay), so the question tests OSPF rather than recognising the word "cost".
- **Question 1609:** the diagram title said "denied path" for a question about an Allow entry.

## No more answers given away by length

In 21 questions, the right answer was more than four characters longer than every wrong option, so a learner could pick the longest option and be right. Seventeen were original questions and four were newer ones. Each key is now trimmed or the wrong options are lengthened, without changing what the answer means. Some wrong options were also swapped for more plausible ones, such as Intrusion Prevention Service in place of APT Blocker for blocking streaming applications.

Across the question bank, the right answer is now the longest option in 15% of Local Firebox questions, 15% of Network+ questions and 7% of WatchGuard Cloud questions, below what chance would give. A new test fails if any single-answer question's key becomes clearly longer than all its distractors again, or if the key is the longest option in more than 35% of questions.

## Mock exams still ask each fact once

Version 1.13.0 grouped questions that test the same fact, so a mock exam asks each fact only once. Many of those groups no longer apply, because the rewritten questions now test different facts. The list goes from 58 groups to 41:

- **Removed:** groups whose questions now test different facts.
- **New (six groups):** each pairs a rewritten question with an older one that still covers the same fact:
  - Default Threat Protection overriding an allow policy
  - keeping management access narrow
  - an IPS signature exception
  - the CLI on TCP 4118
  - a cloud change that has to be deployed
  - a static route that needs a reachable gateway
- **Extended (two groups):** mobile VPN connectivity, and trusting the Proxy Authority certificate.

## Verification

- `npm run lint` is clean, and 316 tests pass across 36 files.
- The NSE and Network+ blueprint tests pass unchanged. No question changed its track or category.
- The same-fact tests pass: groups are valid, and 150 seeds of mock exams in each track never contain two questions from one group.
- The new answer-length test passes for all 630 bank questions.
- In the browser, the Flashcards search finds the rewritten Force Key Expiration card.

## Compatibility

Question IDs, topics and tracks are unchanged, so blueprint weighting, weak-point decks and spaced repetition keep working. Because the rewritten questions ask something new, a learner's earlier result on one of those IDs reflects the old wording. It will update the next time the question comes up. A quiz already in progress keeps the version of each question it started with.
