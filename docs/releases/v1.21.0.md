# Version 1.21.0 — What's New, in the learner's language

The portal has shipped 28 releases and told nobody. `docs/releases/` is a good
record for whoever is reviewing a pull request and the wrong thing entirely to
put in front of someone who came here to study: it talks about key-derivation
schemes, `PRAGMA user_version`, and which assertion moved. This release adds
the other half.

## A section, not a dump of the release notes

`src/data/changelog.ts` is a curated, typed list: version, date, a headline,
and a few changes each tagged **New**, **Better** or **Fixed**. Twenty entries
covering everything back to 1.2.0, written for a learner.

It is curated rather than generated on purpose. The alternative — bundling
`docs/releases/*.md` and rendering it — costs 152KB in the client and shows
people sentences like "the migration drops it (`PRAGMA user_version=3`)". A
changelog nobody can read is not a changelog.

Rendering reuses `parseBold` from `src/utils/textFormatting`, so `**bold**` and
`` `code` `` work and nothing else does. No markdown dependency was added, and
nothing goes through `dangerouslySetInnerHTML`, which keeps the Content
Security Policy honest.

## The part that keeps it from rotting

A hand-written changelog decays the moment somebody forgets it, and a decayed
changelog actively misleads — it says nothing has changed.

`src/data/changelog.test.ts` fails the build when a `docs/releases/vX.Y.Z.md`
exists with neither a changelog entry nor a line in `INTERNAL_ONLY`. That fires
on the pull request that introduced the release, not months later. Releases
that genuinely have nothing to show a learner — dependency removals, container
plumbing — are listed in `INTERNAL_ONLY` with a one-line reason and shown in a
collapsed "Releases with nothing to see" list, so the gap between two versions
is always accounted for.

The rest of the test covers what makes the list readable: newest first by
*numeric* version, dates that parse, headlines that do not repeat the version
number, every change ending in a full stop, and balanced `**` and backticks so
formatting never leaks as literal asterisks.

## The unread count

The navigation item carries a badge with the number of releases since this
device last opened the list. Opening it clears the badge on the way in rather
than the way out, so it does not sit there while you read.

A device that has never opened the list records where it came in and shows
**zero**, instead of meeting a new learner with a badge for twenty releases
they were never here for.

The marker is `watchguard-changelog-seen-v1` in `localStorage`, deliberately
outside `STUDY_KEYS` so it never reaches the server. It is a convenience, not
study progress; syncing it would put another per-person field on the server for
no benefit. `docs/privacy.md` records it alongside the other device-local keys.

## Two bugs found by running it rather than by testing it

**Dates were a day early.** `new Date('2026-09-28')` parses as UTC midnight,
which formats as the 27th for every reader west of Greenwich — so a release
dated today appeared to have shipped yesterday. `releaseDate()` builds the date
from its parts instead, and a test asserts every entry formats back to its own
ISO date.

**A magic number in an existing test.** `lazySection.test.tsx` asserted there
were exactly 7 lazily-loaded sections, so adding an eighth failed it. The count
was never the property being protected — the next line already catches a lazy
import that bypasses `loadSection`. It now asserts that *every* `lazy(` call in
`App.tsx` goes through `loadSection`, with a floor so deleting them all cannot
pass. That is strictly stronger than the number it replaces, and it stops
teaching people to bump a constant.

## Verification

- `npx vitest run` — 40 files, **356 tests**, green. `npm run lint` and
  `npm run build` clean.
- Driven in a production build against a scratch database: set a device's last
  seen release to 1.15.0, confirmed the badge read **5**, opened the section,
  confirmed all 20 entries render with their version, date and change tags,
  confirmed the badge cleared and the stored marker advanced to the newest
  version.
- Checked at 375px: the navigation becomes a grid and the badge corners its
  tile rather than pushing the label.
- The date bug was caught in that run, fixed, and re-verified in the browser —
  the first pass rendered "September 27, 2026" for a release dated the 28th.
- No Docker on this machine; CI's container job covers the image.

## Ordering

are still in review. Once those land, this branch needs a rebase and two more
changelog entries — and the test above will insist on them rather than letting
them be forgotten.
