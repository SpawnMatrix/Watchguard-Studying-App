# Version 1.27.6 — TypeScript 7, and React's types for the first time

The last of four dependency-upgrade releases. It is also the one that found
something about the codebase rather than the dependency.

| Package | From | To |
| --- | --- | --- |
| `typescript` | 5.8.3 | **7.0.2** (the native compiler) |
| `@types/react`, `@types/react-dom` | *not installed* | **19.2.x** |

## What TypeScript 7 exposed

TypeScript 7 turns `strict` on by default. The first `npm run lint` on it
reported **4,329 errors**, almost all of them TS7016: *could not find a
declaration file for module `react`*.

**`@types/react` and `@types/react-dom` had never been installed.** Under
TypeScript 5.8 without `strict`, a missing declaration file silently becomes
`any`, so `npm run lint` passed while every React API was untyped: hooks,
refs, event handlers, and the attributes of HTML elements in JSX.

Props on the portal's **own** components were still checked, because those
are typed by the components' own signatures. So the gap was narrower than
"React unchecked", but real. A probe file containing four mistakes shows it:

```tsx
const [count] = useState<number>('not a number');
ref.current.focus();                       // ref may be null
<button disabled="yes" onClick={e => e.target.value.trim()}>
```

| | Errors reported |
| --- | --- |
| Before: TypeScript 5.8, no React types | **0** |
| After: TypeScript 7, `strict`, React types | **4**, one per mistake |

## Measuring the options before choosing

| Configuration | Errors |
| --- | --- |
| TS 7 defaults (`strict`), no React types | 4,329 |
| TS 7, `strict: false`, no React types | 0, the old blind spot |
| TS 7, `strict: false`, React types | 0 |
| **TS 7, `strict: true`, React types** | **8** |

The codebase was eight fixes away from fully strict checking, so it is now
strict, rather than pinning `strict: false` to keep the old behaviour.
`tsconfig.json` says `"strict": true` explicitly, so the setting does not
depend on a compiler default.

## The eight fixes

- **`server.ts`, three tutor routes.** They take their middleware as an
  array (`tutorGate`), and Express 5's types cannot infer `req` and `res`
  through one, so both were implicitly `any`. They are now annotated as
  Express `Request` and `Response`.
- **`AIChatMode`'s `scrollRef` prop.** React 19's types make
  `useRef<T>(null)` a `RefObject<T | null>`, and the prop now says so.
- **A sandbox engine test** read `trace.at(-1)` without allowing for an absent
  trace. It now uses optional chaining.

None of these was a runtime bug. They are places where the checker could not
see, and now can.

## What stays the same

TypeScript only type-checks here. Builds and tests transpile with Vite/Oxc,
esbuild and tsx, so no emitted code changes. Type-check time fell from several
seconds to about 1.4 s.

## Verification

- `npm run lint` (`tsc --noEmit` on 7.0.2, strict): 0 errors.
- The probe above: 0 errors on the old setup, 4 on the new one. The probe file
  was not committed.
- `npx vitest run`: 58 files, 483 tests, green. `npm run build` clean.
  `npm audit`: 0.
