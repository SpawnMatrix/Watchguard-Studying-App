# Version 1.22.1 — A review pass: readable answers, real fonts, honest numbers

A review of the whole portal against `main` at 1.22.0. Everything was green:
lint, 405 tests, the build, the release gate. It still turned up defects a
learner sees on every visit, one stranded fix, and a README that undersold the
bank on every headline number. This release fixes those and adds a test for
each, so none of them can come back unnoticed.

## The correct answer was the hardest text to read

In light mode, after **Check answer**, the correct option rendered in Tailwind's
`text-green-400` on white: **1.78:1** contrast, against the 4.5:1 WCAG AA asks
for body text. The wrong pick was 2.89:1. Options the learner had not picked
were grey *and* `opacity-60`, which made them hard to read in both themes.

The fix was written on 14 September on `codex/topology-ui-validation` and never
opened as a pull request. It is ported here, adapted to the code that has
changed since:

- Submitted options carry `data-answer-state` (`correct`, `incorrect`,
  `other`), and light mode maps those to `#047857` and `#b91c1c`. Measured in a
  production build: correct **5.48:1**, wrong pick **6.47:1**, others 7.58:1.
  Dark mode: 9.40, 5.79 and 6.43.
- The `opacity-60` stack on unpicked options is gone in both themes.
- `src/engine/answerState.ts` holds the answer key and state. Both quizzers
  duplicated `correctAnswers || [correctAnswer]` inline, and
  `TopologyQuizzer` passed the diagram `question.correctAnswers` without that
  fallback. Every question in today's catalog has the array, so this only bit
  sessions saved by older builds, where the diagram would mark nothing correct
  while the buttons below it did.
- Diagram nodes that are answers get a tick, a cross or a dot, so the verdict
  does not depend on colour vision. **Edges deliberately do not.** The original
  branch put an edge's marker at the edge's midpoint, which is where the edge
  label sits — and 1.18.1 was a release about diagram labels being obscured.
  Edges keep their colour, a thicker stroke and an accessible label that states
  the verdict.

## The fonts never loaded in production

`src/index.css` began with an `@import` from `fonts.googleapis.com`. The
production CSP (`style-src 'self' 'unsafe-inline'`) blocked it, so every page
load logged a CSP violation and the portal rendered in system fonts. Inter,
Space Grotesk and JetBrains Mono have never appeared in production.
`docs/privacy.md` already listed this as open: relaxing `style-src` later would
have quietly sent every visitor's address to Google.

The fonts are now bundled from `@fontsource-variable/{inter,space-grotesk,jetbrains-mono}`
(OFL-1.1) and served from the portal's own origin. Each face is split by
`unicode-range`, so an English page fetches three Latin files, about 111 kB in
all and cached after the first load. No CSP change was needed, because
`font-src 'self' data:` already covered them. The theme's stacks name the
bundled `… Variable` families first.

`src/selfHostedAssets.test.ts` fails if `index.html` or any stylesheet under
`src/` references another origin, if a bundled font package would fetch
anything but its own relative files, or if a theme stack starts with a family
no bundled package declares. It was checked against the old import and failed
as it should.

**This is a visible change for anyone on a live deployment.** Headings switch
from the system sans to Space Grotesk, body text to Inter, and code to
JetBrains Mono — the design the source always asked for.

## The README undersold the bank

| Claim | README said | Catalog has |
| --- | --- | --- |
| Authored questions | 630 | **658** |
| Local Firebox items (NSE blueprint pool) | 485 | **490** |
| Network+ items (N10-009 blueprint pool) | 174 | **181** |
| Scenario templates | 42 | **62** |
| Flashcards | 300 | **489** |

`src/data/readmeCounts.test.ts` reads nine figures out of the README —
including the diagram, multi-select, checkpoint and fault-type counts, which
were still right — and compares them with the catalog. A content PR that changes
a count now fails on that PR, and the message names the sentence to edit. Run
against the 1.22.0 README, it flagged exactly the five rows above.

## Smaller things

- A brand-new learner was greeted "Welcome back". Study Home now says
  "Welcome" until there is an answer, a finished lab or a saved quiz.
- `npm audit` reported three moderate advisories: `qs` through Express, and
  `@vitest/mocker` in dev. Express moves 4.22.2 → 4.22.3 (`qs` 6.16.0), and
  `vitest` with `@vitest/coverage-v8` move 4.1.10 → 4.1.11. `npm audit` now
  reports 0.
- Two empty files committed at the repository root by a mistyped command,
  `node` and `react-example@0.0.0`, are removed.
- `docs/privacy.md` records the font import as resolved.

## Verification

- `npm run lint` clean. `npx vitest run`: 46 files, **420 tests**, green (15 new).
  `npm run build` clean. `node scripts/check-release.mjs origin/main` passes at
  1.22.1.
- Driven in a production build (`NODE_ENV=production`, scratch `DATA_DIR`):
  - After the fix, the console logs no CSP error. A marker logged before a
    reload confirmed the remaining entries came from earlier loads.
  - `document.fonts` reports all three bundled faces loaded, and the network
    shows only the three Latin `.woff2` files, all same-origin.
  - The contrast figures above come from computed styles after **Check
    answer**, with transitions disabled. A frozen mid-transition colour gave a
    false reading the first time.
  - A cleared browser shows "Welcome, reviewer."
- The diagram markers are verified by `topologyFeedback.test.tsx`, not by
  hand. Only one of the 16 diagram scenarios has node hotspots, and the preview
  pane's frozen animations stopped me from launching it in place.
- No Docker on this machine; CI's container job covers the image.

No schema change, no new route, no new server-side data. The deploy picks up
new static assets only. The branch is delivered by pull request and does not
deploy itself.
