# Version 1.30.4 — Erasing answer history asks first, and can be undone

"Reset statistics" sat beside Check answer, 29px away on a 390px phone. One
tap erased every answer on all three tracks, with no confirmation. That
history is what Study Home, exam readiness, the exam planner and weakness
review are built from. For a signed-in learner, the account sync then sent
the empty history to the server about 0.6 seconds later, so the server copy
was gone too.

## What changed

- The button is now **Erase answer history**, inside Practice settings and
  closed by default. It is disabled when there is nothing to erase, and it
  shows how many answers it would remove.
- It asks first, with the count, and says that other devices receive the empty
  history, and that flashcards, labs and the spaced-repetition schedule are not
  affected. `FlashcardStudio` already confirmed its own reset the same way.
- Afterwards, "Erased N answers. **Undo**" stays until the learner leaves
  Practice. Undo puts the erased answers back ahead of any given since, so
  answers given since are kept too.
- The answer row holds only Check answer / Next question now, still on the
  right.

## Verification

- `src/components/historyReset.test.tsx`: the button is in Practice settings
  and not in the answer row, it is disabled with no history, the confirmation
  wording, and that Undo keeps later answers.
- Production build at 390px, device-only learner, 3 answers. Cancelling the
  confirmation kept all 3; confirming erased them and showed "Erased 3 answers"
  with Undo. One more answer, then Undo, gave 4. Screenshot of the drawer
  inspected.
- `npm run lint`, `npx vitest run` (62 files, 519 tests), `npm run build`, and `scripts/check-release.mjs` against the parent branch and `origin/main` all pass locally. CI's container job runs on the PR; no local Docker here.
- Not verified with a signed-in account across two devices: the undo writes
  the history back and syncs it like any other change, but I did not watch a
  second device receive it.

## Deploy impact

Client-only. No server, schema, Compose or image change.
