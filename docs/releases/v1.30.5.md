# Version 1.30.5 — Fresh scenarios no longer give the answer away

`src/data/answerLength.test.ts` guards the hand-written bank, which measures
16% key-longest with no giveaways. Nothing measured the 62 generated
templates, which make up much of mixed practice and mock exams. Sampling 60
variants of each:

| | Before | After |
| --- | --- | --- |
| Key is the longest option | **51%** | **20%** |
| Key more than 4 characters longer than every distractor | 871 of 2,220 | **0** |
| Templates where the key is longest in every variant | 18 | 6, by 1–4 characters |
| Key's length rank (longest / 2nd / 3rd / shortest) | 55/25/14/6% | 30/36/23/11% |
| Options more than 30% apart in length within a question | 55% | 14% |

The worst cases were the Traffic Monitor scenarios. Anti-spoofing's answer ran
103 characters against 57–60, and BOVPN's ran 120 against 36–46.

## What changed

- Trimmed the correct answer in 18 templates (10012, 10016, 10019, 10020,
  10021, 10025, 10029, 10054, 10101–10108, 10111, 10116). The cut
  clauses restated the explanation, and the explanations are unchanged except
  where noted below.
- Replaced throwaway distractors ("A longer DNS TTL.", "In a DNS TXT record.",
  "Change the DHCP subnet mask.") with misconceptions a learner could hold. For
  example: a larger subnet mask so the DHCP broadcast reaches the server; Phase
  1 encryption when Phase 1 already works; Firebox System Manager as the place
  to configure policy. The explanations of 10021 and 10029 now say why those
  are wrong.
- Some keys are deliberately still the longest, by 1 to 4 characters. A
  template that is never key-longest is the same tell inverted.
- `src/engine/templateLength.test.ts` samples every template and fails on any
  key more than 4 characters longer than every distractor, a key-longest share
  outside 15–35%, any length rank above 50%, or more than 20% of questions with
  options over 30% apart. It fails 4 of its 5 checks against the old
  templates.

## Verification

- Measured with the scripts above. Also checked with `validateQuestion`: no
  invalid questions, duplicates or new prefix collisions. The only prefix
  matches are IP addresses such as 10.73.15.3 and 10.73.15.31, in templates I
  did not touch.
- The authored bank is unchanged. Question and template counts are unchanged,
  so `scripts/smoke.mjs` needs no update.
- `npm run lint`, `npx vitest run` (63 files, 524 tests), `npm run build`, and `scripts/check-release.mjs` against the parent branch and `origin/main` all pass locally. CI's container job runs on the PR; no local Docker here.
- Not verified against a published source beyond the existing explanations and
  page references. The new distractors are wrong for reasons stated in the
  explanations, and I did not invent new exam criteria.

## Deploy impact

Content only. No server, schema, Compose or image change.
