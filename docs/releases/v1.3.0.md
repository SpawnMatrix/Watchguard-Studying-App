# Version 1.3.0 — the complete lab catalogue

The Lab Exercises catalogue held 8 of the 20 exercises in WatchGuard's Network Security Essentials Lab Book, numbered 1, 6, 8, 11, 14, 15, 12, 13 — gaps throughout, and the last two displayed out of order because the catalogue rendered its source array with no sort. This release completes it and gives it the browsing controls twenty labs need.

- All 20 Lab Book exercises are present, numbered to match the Lab Book (Fireware v12.5.9/12.7.2), across 81 walkthrough steps. The catalogue rebuild came from the `feature/expand-lab-book-and-sandbox` branch, which had done that work and never landed; only the lab data is taken from it, since the sandbox and simulator changes there are a separate concern.
- Labs sort by number, by category, or by name. Lab number is the default because the Lab Book is numbered that way and the exam follows it.
- Labs filter to one of seven categories: Setup & Management, Networking & Routing, Policies & Proxies, Security Services, Authentication, VPN, and Logging & Reporting.
- Eight labs need equipment beyond one Firebox and a management PC — a second appliance, an Active Directory domain controller, or a Dimension or WatchGuard Cloud subscription. Those prerequisites were already stated rather than faked, and are now a structured flag as well, so a single toggle narrows the catalogue to the twelve labs a learner can run with the hardware in front of them. Each card shows its category and, where it applies, that it needs extra kit.
- The catalogue shows how many labs the current filters leave, and explains itself when a combination excludes every lab rather than rendering an empty list.
- Progress reports recommend labs by identifier, so the renumbering would have pointed them at the wrong exercises. The topic-to-lab mapping is corrected, and extended to cover WatchGuard Cloud, IP Addressing, Network Services and Network Operations, which previously produced no recommendation at all.
- Sorting and filtering live in a pure `orderLabs()` helper rather than inside the component, and `src/data/labs.test.ts` covers the shape that regressed: twenty contiguous sorted identifiers, every lab categorised with steps numbered from one, no empty category, and the case where filters exclude everything.

Also on `main` since 1.2.0, which shipped without release notes of its own: log-analysis scenarios went from 8 to 16 and policy-ordering exercises from 4 to 10, and the question bank reached 496 items with multi-select raised from 10% to 15%.

No SQLite migration, volume replacement, deployment-script update, or topology v1 contract change is required. Lab progress is recorded against lab identifiers, and the renumbering means historical completions recorded under the previous numbering refer to different exercises; the counts remain valid, the specific labs they name do not. Keep the persistent data volume when deploying. This branch is delivered by pull request; it does not merge or deploy itself.
