# Version 1.4.0 — Firebox-style sandbox workspace

The Network Sandbox now follows a locally managed Firebox workflow: Front Panel, Firewall Policies, Policy Test, and Traffic Monitor. Its existing six guided challenges and deterministic packet decisions remain intact.

- Front Panel summarizes allowed traffic, firewall denies, and client TLS failures separately, with an interface diagram and a troubleshooting loop.
- Firewall Policies presents every existing teaching rule in a readable table with source/destination scope, service, and inspection behavior. Blocked Sites, Blocked Ports, and client CA trust remain configurable.
- Policy Test provides six valid traffic presets, editable flow inputs, and links back to policy settings. Re-test any historical flow against the current configuration while preserving the original trace.
- Traffic Monitor filters by IP, service, policy text, and outcome. Client TLS failures are not counted as firewall denies. Export and the 50-flow history limit are preserved.
- Responsive layouts support both themes. JavaScript packet animation respects reduced-motion preferences.

This is an independent teaching simulation inspired by Fireware workflows, not a full emulator or an official WatchGuard interface. NAT, VPN, routing failures, return sessions, and the complete Fireware policy-order algorithm remain outside its scope. Configuration and challenge completions remain scoped to the current sandbox visit.

No database migration or deployment configuration change is required. Account administration is unchanged; production role grants are operational changes, not part of this release.
