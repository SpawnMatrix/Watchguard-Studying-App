# Version 1.27.2 — Easier to read everywhere, in both themes

1.22.1 found the correct answer rendering at 1.78:1 contrast in light mode,
after 22 releases in which nothing looked. This release adds something that
looks on every pull request, and fixes what it found the first time it ran.

## The check

`scripts/a11y.mjs` drives the production build in Chromium with Playwright and
runs **axe-core** against WCAG 2.1 A and AA on:

- the account gate, the first screen anyone sees;
- all ten sections, entered through the gate the way a learner enters them;
- the quiz **after an answer is checked**, where the 1.22.1 bug lived. It
  switches to multiple choice first, so the random first question always has
  options to pick;
- each of those in **dark and light**: 24 screens in all.

It fails on any violation not explained in `scripts/a11y-allowlist.json`, which
is empty. A new **`a11y` job** in `study-checks.yml` builds, starts the server
and runs it, gated on the release check like the test job. Locally:
`A11Y_URL=http://127.0.0.1:3000 npm run a11y`.

## What it found

The first run: **23 failing groups**, all `color-contrast`. Every other rule
passed: labels, names, roles, landmarks and ARIA use. Grouped by colour pair,
they reduced to a handful of causes, so they were fixed as theme tokens, not
element by element:

| Theme | Was | Contrast | Now | Contrast |
| --- | --- | --- | --- | --- |
| Dark | `text-gray-500` #6a7282 on panels | 3.45:1 | #8f99aa | ≥ 5.03:1 on every dark surface |
| Dark | `text-gray-600` #4a5565 | 2.3:1 | #8a94a6 | ≥ 4.73:1 |
| Dark | white on `bg-watchguard-orange` #ed633d | 3.25:1 | #c94826, as `.primary-button` already used | 4.73:1 |
| Dark | orange text on orange-tinted tags | 4.35:1 | brand text #f27a57 | ≥ 4.5:1 on a 20% tint |
| Light | orange text on white / on the active-nav tint | 3.25 / 2.79:1 | #a63416, already the light heading colour | 6.72 / 4.84:1 |
| Light | `green-400` text (What's New, scores, results) | 1.77:1 | #047857 | 5.48:1 |
| Light | `red/sky/blue/indigo-300/400` text | < 3:1 | #b91c1c / #0369a1 / #1d4ed8 / #4338ca | 5.9–7.9:1 |

Each replacement was computed against every surface it sits on before it was
applied, not picked by eye: the dark panels at #10151e, #141a25, #171e2a and
#202a39, the light ones at #ffffff, #f8fafc and #f1f5f9, and 10–20% tints.
Light mode's Tailwind status colours were made for dark backgrounds, and this
release fixes them app-wide. 1.22.1 had fixed them only on the answer buttons.

Second run: 4 groups left. Third run: **no violations on all 24 screens.**

## What changes visually

- Dark mode's small grey labels are a little lighter.
- The brand orange is a touch lighter as text in dark mode and a deeper rust in
  light mode.
- Orange buttons with white text are slightly darker in dark mode.
- Light mode's green, red and blue status text is a deeper shade.

Checked by screenshot in both themes.

## Not covered

- axe checks what is rendered in each state it visits. Dialogs, expanded
  accordions, a finished lab and the Ideas board with posts in it are not
  visited.
- Some things cannot be automated at all: focus order, meaningful link text in
  context, screen-reader flow. This is a floor, not a substitute for testing
  with assistive technology.
