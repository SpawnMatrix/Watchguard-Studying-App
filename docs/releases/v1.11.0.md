# Version 1.11.0 — Three more hands-on labs: SD-WAN, proxies and authentication

Version 1.10.0 made six labs hands-on. This release adds the three single-Firebox labs that build on them, bringing hands-on labs to nine of the twenty. Each one starts from the finished state of the lab it depends on, so you pick up where the Lab Book expects you to be.

## Lab 8: Link Monitor and SD-WAN

The simulator gains **Network > Link Monitor**, **Network > SD-WAN** and **System Status > SD-WAN**.

- **Link Monitor:** monitor External with Ping, DNS and TCP probe targets, choose which probe measures loss, latency and jitter, and give DMZ a next hop.
- **SD-WAN:** build an action and route the Ping policy through it.

Nothing answers on the DMZ network, so Link Monitor marks DMZ inactive. The Ping policy's traffic is then dropped with "all gateways are down", which is exactly what the lab's step 5 expects. If you add External to the action after DMZ, traffic fails over to it.

## Lab 11: Proxies

The simulator gains **Firewall > Proxy Actions**: URL Paths rules on Default-HTTP-Client, plus the no-match action on Default-HTTPS-Client. The management PC gains the **Certificate Portal**.

The lab's lesson plays out in order:

1. **Before inspection,** a search for "example" over HTTPS loads, because the proxy can only see the host name.
2. **With inspection turned on,** every HTTPS site shows a certificate warning until the Proxy Authority certificate is installed as a trusted root.
3. **After installing it,** the same search is blocked by the `*example*` rule. The Traffic Monitor line shows the rule and that the session was inspected.

## Lab 14: Authentication

The simulator gains **Authentication > Servers** (Firebox-DB users and groups), **Authentication > Settings** and **System Status > Authentication List**. The management PC gains the **authentication portal** on port 4100.

- **Scope the proxies to your group,** and unauthenticated browsing stops.
- **Turn on automatic redirect,** and browsing sends you to the portal instead.
- **Sign in,** and web traffic flows again, with `src_user` in Traffic Monitor and your session in the Authentication List.

## Also

- Policy editing now covers the From list and the SD-WAN action, not only To.
- Backup images include the new configuration, so Link Monitor, SD-WAN, proxy and authentication settings survive a restore.

## Verification

- For Labs 8, 11 and 14, every task is unmet before its step and verified after doing exactly what it asks.
- Behaviour tests cover URL pattern matching, when URL rules apply inside HTTPS (no inspection, an untrusted CA, then a trusted CA), SD-WAN failover and dropping, Link Monitor validation, group-scoped policies with redirect and sign-in, and restoring the new settings.
- All three labs were played through with the real forms in the browser.

As before, this is a teaching simulation of the behaviour these labs exercise, not Fireware. No server, database or deployment change is required.
